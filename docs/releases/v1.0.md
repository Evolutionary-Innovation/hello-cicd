# v1.0 Release

Release date: 2026-10-18. First release of the platform as a reusable template.

## Release notes

### Highlights

- **Push-to-deploy pipeline**: infrastructure, image build and deployment chained in GitHub Actions, one entry point, each stage also runnable alone.
- **No stored credentials**: GitHub-to-AWS authentication by OIDC; deployment over SSM; no SSH, no key pair, no deploy secrets.
- **Least-privilege CI role**: `AdministratorAccess` replaced by a project-scoped policy derived from CloudTrail evidence and tested, including negative tests.
- **Safe deployments**: immutable SHA-tagged images, `/health` that reports the deployed commit, health-gated deploys with automatic rollback.
- **Reusable template**: one variable (`project_name`) drives every name and tag; `scripts/configure-project.sh` rewrites the per-project values; full documentation set including a Template Migration Checklist.
- **Proven recovery**: complete destroy of the main stack and rebuild through the pipeline under the scoped role.

### Changes since the pre-release platform

- IAM: scoped CI policy; role keeps its existing name/ARN; admin attachment retired.
- Terraform: `project_name`/`environment` tags and naming, backend settings in `backend.hcl`, `ecr_force_delete`, new outputs (`app_url`, `ecr_repository_name`, `container_name`, `app_port`), `public_dns` removed, key pair removed, ECR resources renamed with `moved` blocks (since removed).
- Instance: standard AL2023 AMI, SSM agent installed by `user_data`, encrypted root volume, IMDSv2 required, AMI changes ignored (no surprise replacement).
- Pipeline: `wait-for-instance.sh` (SSM registration and cloud-init), docs-only pushes skipped, no verify/show-state noise.
- Application image: non-root user, `.dockerignore`, `GIT_SHA` baked in, `PORT` honoured.
- Docs: README, 15 guides, repository review report.

### Upgrade notes for pre-release deployments

The live deployment was rebuilt once during this release (new Elastic IP). Existing projects created from earlier copies of the repository should re-apply `bootstrap/` (to attach the scoped policy) before pulling the new workflows.

## Architecture summary

Two Terraform stacks. `bootstrap/` (human-applied) owns the S3 state bucket, the GitHub OIDC provider and the CI role plus scoped policy. `terraform/` (CI-applied) owns one EC2 instance (AL2023, Docker, SSM), an Elastic IP, a single-ingress security group, an ECR repository with a lifecycle policy, and the instance role/profile. GitHub Actions runs `infrastructure -> build -> deploy`; deploy talks to the instance only through SSM Run Command and verifies `GET /health` over HTTP. Terraform outputs are the single contract between stages. See [Architecture](../architecture.md).

## Security summary

- Identity: OIDC, trust pinned to audience, numeric owner/repo IDs and the `main` branch; no AWS keys anywhere.
- Authorisation: scoped customer-managed policy (resource names, `project` tag, region, managed-policy allow-list, PassRole restricted to EC2); CI cannot reach the bootstrap state, IAM outside the instance role, or other S3 buckets.
- Host: no port 22, no key pair, IMDSv2 required, encrypted EBS, minimal instance role, non-root container.
- Supply chain: immutable SHA tags, scan on push, SHA visible through `/health`, plan applied as saved.
- Open items (see [Security](../security.md)): branch protection, TLS, action pinning, monitoring.

## Lessons learned

1. **Prove IAM from evidence.** Building the policy from CloudTrail and then running the real `terraform plan`, state/ECR/SSM operations and negative tests found the problems (for example the SSM document ARN versus instance ARN conditions) before the cutover, so the switch was uneventful. Keep a temporary role for testing and delete it afterwards.
2. **Standard images matter.** The minimal AL2023 AMI has no SSM agent; a deploy-time workaround worked but masked the real fix. Choose the AMI that matches the operating model.
3. **Do not use `/tmp` markers.** `/tmp` is cleared on reboot; `cloud-init status --wait` is the right readiness signal.
4. **Auto-apply plus a floating AMI is a trap.** `most_recent = true` would have replaced the server on an unrelated push. Pin behaviour with `ignore_changes` and patch deliberately.
5. **Backend blocks cannot use variables.** Externalise to `backend.hcl` and generate it in the template script.
6. **Name from one variable, scope permissions by tag.** The same `project_name` gives naming, tags and IAM conditions, which is what makes the template reusable and the policy meaningful.
7. **Verify that a push actually landed.** An interrupted command once left a local "revert" commit that was really the broken change under a new message; comparing local and remote refs caught it before it shipped. Check `origin/main`, not memory.
8. **Rebuilds find what steady state hides.** The first destroy/rebuild after hardening validated the scoped role's create paths, the AMI/user-data combination and SSM registration timing in one run.
9. **Unauthenticated API polling runs out.** GitHub's 60 requests/hour limit is easy to exhaust when watching runs; authenticate `gh` or poll the application instead.

## Known limitations

- **Single instance, single AZ, default VPC.** An instance or AZ failure means downtime until rebuild.
- **Brief interruption on each deploy** (stop old, start new); no blue/green.
- **HTTP only**, app port open to the internet; no TLS or WAF.
- **Public IP changes on rebuild**; there is no DNS.
- **No monitoring or alerting**; health is checked only during deploys.
- **No host image pruning**; old images accumulate on the 20 GB root volume.
- **Rollback depth** is the last 10 tagged ECR images; infrastructure changes are not rolled back by the deploy job.
- **One OIDC provider per account**: a second project in the same account must import it (see [Bootstrap](../bootstrap.md)).
- **Manual steps remain**: bootstrap apply, two GitHub variables, branch protection, removing the stale `EC2_SSH_KEY` secret, creating the GitHub Release object.
- **ECR scan findings are not enforced**, GitHub Actions are tag-pinned.
- **Stateless only**: no database, backup or migration handling.
